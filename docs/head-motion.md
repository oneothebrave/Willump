# StackChan 头部姿态

当前头部代码为 `2026.10.26-r1`，修复重启时切断舵机供电、尚未连接即回平和初始化迟就绪后不能恢复的问题。
保存的校准为 `591`、自动开关为 `1`。历史连接策略见 [2026-10-20 记录](head-connection-2026-10-20.md)，
本轮重启验收见 [2026-10-26 记录](head-reboot-2026-10-26.md)。

本机人工确认的水平基准为 raw=591，抬头目标为 raw=655，约 **20°**；原厂 zero=599 只读。
此前按工作状态决定姿态的策略已被后台连接策略替代。

仅控制 ID 2 俯仰舵机：UART1、1Mbps、TX6/RX7，PY32 IO0 供电。使用官方 StackChan-BSP 的最小驱动子集，保留来源和许可证。不向 ID 1 或广播地址发送运动命令，不改写原厂校准。

| 后台连接 | 目标 |
| --- | --- |
| 开机尚未收到第一次合法 hello | 保持当前姿态，不主动回平 |
| 收到合法 `bridge.hello`，协议连接就绪 | 立即请求水平 +64 原始单位，约 20° |
| 已有合法连接后，后台关闭、WebSocket 或 Wi-Fi 断开 | 人工确认的水平位置 |

回平须等断线稳定 350ms；抬头请求立即执行，可以抢占尚未完成的回平动作。
移动命令仍为 900ms 平滑移动。已到目标且扭矩启用时，重复状态不重复发命令。
扭矩停用后重新启用，即使目标没变也会重新发送位置并恢复扭矩。

空闲、工作、等待、完成和异常事件都不改变头部目标。只要后台连接有效就保持抬头；
后台停止且设备检测到断线后回水平。重连须再次收到合法 hello 才抬头。

启动恢复采用非阻塞状态机：UART 就绪后开启或保持 VM，预热 2000ms，随后读取 ID 2 位置。
启动和重试均不主动切断 VM，避免释放抬头姿态的支撑和反复打断舵机启动。
位置读取失败后间隔 2 秒重试，最多 3 次；之后只做每 2 秒一次的只读探测。
舵机迟就绪后可以恢复，成功读取前不发送运动命令；后台连接变化或显式 `e` 可重新开始初始化。
初始化期间已经观察到的有效连接不会在初始化成功时被清除。
初始化失败时仍能使用 `v` 查看状态、`e` 请求恢复和 `x` 保存禁用配置。
未校准设备仍执行只读位置初始化，以便人工使用 `h` 保存水平位置；有效校准保存前不会自动移动。

位置必须在 0–1000，水平校准必须在原厂零点 ±16 原始单位内，运动范围限制在水平至水平+64。无有效校准时不自动运动。通信应答或舵机状态异常会记录失败，至少间隔 1 秒再试，最多 3 次；随后保持故障锁定，须显式 `e` 或手动调试命令恢复。故障不根据显示状态变化无限重试。

串口命令（115200）：

| 字符 | 行为 |
| --- | --- |
| `v` | 读取版本、ready、水平、目标、位置反馈、自动模式、运动故障、启动重试次数、通信错误与后台连接状态 |
| `h` | 保存已人工确认的当前水平位置，关闭自动模式 |
| `u` | 临时手动抬头 5°，关闭本次运行的自动模式 |
| `n` | 临时手动回水平，关闭本次运行的自动模式 |
| `e` | 恢复自动模式与重试能力，并保存启用配置；未就绪时重新执行有限启动恢复 |
| `x` | 停止自动模式、关闭俯仰扭矩并保存禁用配置 |

设置保存在独立 NVS `indicator-head`。常规烧录不擦除该分区。新设备必须重新人工校准；不能复用本机 591 或把任意开机位置当作水平。

本机回归包含 491 条固件逻辑断言及 77 条实际 HeadMotion 的模拟硬件断言，
覆盖两种初始姿态、全部协议事件、迟就绪舵机、断线/重连、故障重试限额和时钟回绕。
运行方法见 [本机测试](../firmware/stackchan/test/native/README.md)。
反馈与目标有少量差异，不表示角度经过外部测量。

参考：[M5Stack 舵机文档](https://docs.m5stack.com/en/arduino/stackchan/servo)、[StackChan-BSP](https://github.com/m5stack/StackChan-BSP)。
