# StackChan 接入 OpenCode 免费模型方案

## 可行性结论

**有条件可行，建议分阶段实施。**

- 编码模型运行在 Mac 的 OpenCode 中；机器人只负责离线唤醒、录音、状态显示及触摸确认。
- StackChan Core 的 ESP32-S3、双麦克风和 8 MB PSRAM 足以运行 WakeNet/VAD，但 ESP-SR
  与现有 Arduino + PlatformIO 构建体系的兼容性必须先做真机验证。参考
  [ESP-SR 官方文档](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/getting_started/readme.html)。
- Mac 使用 `whisper.cpp` small 多语种模型离线识别中文及英文代码术语；约需 466 MiB
  模型空间和 852 MB 内存。参考 [whisper.cpp](https://github.com/ggml-org/whisper.cpp)。
- OpenCode 已提供会话、异步 prompt、事件流、中断和 permission reply 接口，能够支持完整
  编码代理。参考 [OpenCode Server](https://docs.opencode.ai/docs/server/)。
- 免费模型属于限时供应，不能保证长期存在；只允许在官方明确声明零留存、不用于训练的
  免费模型白名单中回退。参考
  [OpenCode 免费模型](https://dev.opencode.ai/v2/docs/console/models)。

## 实施设计

### 1. 固件可行性闸门

- 增加独立的语音实验构建环境，不立即替换当前稳定固件。
- 启用 ES7210 麦克风、ESP-SR AFE、VAD 和预训练的 “Hi ESP” WakeNet。
- 根据模型大小增加专用模型分区；不得覆盖原厂校准或改变舵机 ID、限位及断线回平逻辑。
- 验证语音功能与屏幕、Wi-Fi、WebSocket、扬声器提示音及头部任务能够共存。
- 如果必须整体迁移生产固件框架才能使用 ESP-SR，停止在闸门处并单独评估迁移，不在本功能中
  静默修改框架。

### 2. 独立语音通道

- 保持现有 `/status` 和 `agent.event` 协议不变。
- 新增经过预共享密钥认证的 `/voice` WebSocket；OpenCode 服务仍只监听 `127.0.0.1`，
  不向局域网暴露。
- 设备端检测到唤醒词后才发送 16 kHz、16-bit、单声道 PCM；VAD 判定一句话结束，最长收音
  15 秒。
- 音频只保存在内存中并送入本机 `whisper.cpp`，不写日志、不保存录音、不向 OpenCode 模型
  供应商发送原始音频。
- 扬声器播放提示音期间暂停麦克风识别，播放结束后恢复，避免自触发。

### 3. 接入 OpenCode

- 在 Willump 工作目录建立一个专用、持久的 `StackChan Voice` 会话；同一时刻只运行一个 turn，
  忙碌时拒绝新语音任务。
- 主模型固定为 `opencode/deepseek-v4.1-flash-free`。
- 主模型不可用时，重新读取供应商信息，只在“当前免费且官方明确零留存、不训练”的配置白名单中
  依次回退；无合格模型则失败关闭，绝不使用付费模型。
- 完整 transcript、模型回答、命令、文件内容和审批详情只出现在电脑端 OpenCode；机器人仅接收
  状态和不透明的会话或审批标识。
- 空白、仅噪声或无法识别的录音不提交；识别文本不得写入 bridge 日志。

### 4. 权限与触摸语义

- 允许在 Willump 内读取和搜索普通源码；拒绝读取凭据、私有配置和工作区外路径。
- 文件修改和 shell 命令统一配置为 `ask`；每次只能批准 `once`，不得通过机器人选择 `always`。
- 电脑显示具体操作内容；机器人审批页右侧触摸为批准一次、左侧为拒绝，15 秒无操作自动拒绝。
- `git commit`、`git push`、烧录、Flash 操作、外部目录访问及明确破坏性命令默认拒绝，不能通过
  机器人解锁。
- 长按屏幕中断当前 OpenCode turn；晚到的音频、事件或审批回复必须按 session、turn 和
  request ID 丢弃。
- 无审批时短按仍保留现有调试页行为。

## 接口与文档边界

- 新增语音消息：会话开始、PCM 音频帧、结束、忙碌、错误和最小审批状态；所有消息带连接或
  session 标识并限制长度。
- 不在设备协议中发送 transcript、模型回答、命令正文、文件内容或审批详情。
- 文档明确新增的唯一隐私例外：经过认证、由唤醒词触发的短时用户音频可从设备上传到本机
  bridge；触摸产生的不透明审批决定可返回本机 OpenCode。
- 模型、录音、密钥和本地 Whisper 构建产物全部排除在 Git 之外。

## 验证与验收

- Node：语音协议边界、认证、大小和时长限制、OpenCode 会话、免费模型回退、并发拒绝、中断、
  审批超时和晚到事件测试。
- 固件：WakeNet/VAD 状态机、重连、重复消息、提示音互斥、审批触摸、中断及现有状态和头部安全
  回归。
- 构建：运行 `npm test`、`npm run build`、相关契约测试、固件逻辑测试及所有 PlatformIO 环境
  构建。
- 真机闸门：
  - 麦克风采样正确，唤醒后只上传一句话；
  - 0.5–1 米安静环境下 20 次唤醒至少成功 18 次；
  - 30 分钟普通环境音测试中无不可接受的误触发；
  - 完成一次只读任务、一次经触摸批准的修改任务、一次拒绝和一次长按中断；
  - 断网、OpenCode 停止和模型不可用时均安全失败；
  - 屏幕、提示音、联网、舵机限位和断线回平均无回归。

## 已确定的默认选择

- 首版采用预训练 “Hi ESP”，不定制 “Willump”。
- 机器人端离线识别唤醒词，每次唤醒只收取并提交一句话。
- Mac 使用 `whisper.cpp` small 多语种模型，仅做语音识别，不实现 TTS。
- 完整结果只在电脑端 OpenCode 查看，机器人只显示状态。
- 使用专用持久会话；忙碌时不接受第二个语音任务。
- 危险操作的详情在电脑显示，机器人触摸仅作为第二因素。
- 长按机器人屏幕取消当前任务。
- 免费模型只在零留存白名单内自动回退，绝不自动使用付费模型。
- 未通过固件可行性闸门前，不继续完整集成，也不烧录生产固件。
